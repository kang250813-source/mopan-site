DS Bot：开源多 AI Agent 协作工具，让不同 AI 助手分工完成任务

Published 2026-11-17

如果你平时会同时使用 Claude Code、Codex 等 AI 工具，可能已经习惯了让不同模型处理不同任务。但当研究、编程和资料整理需要互相配合时，多个独立的 AI 对话窗口就不太方便了，任务交接、上下文共享和进度管理都需要自己处理。

DS Bot 是一款基于 DeepSeek Harness（DSH） 的开源多 AI Agent 协作工具，可以创建多个拥有独立角色、模型、记忆和工作目录的 Bot，再通过主 Bot Chief 统一管理。不同 Bot 可以在群聊中交流、分配任务和提交结果，也能接入 Claude Code、Codex CLI 等本地编程 Agent。

与普通 AI 聊天客户端不同，DS Bot 主要解决的是多个 AI Agent 的组织与协作问题。它提供 Windows、macOS、Linux 桌面应用，也支持 DSH 插件和 Docker 部署。项目并非 DeepSeek 官方产品，模型 API 和第三方 Agent 的使用费用也需要用户自行承担。如果你希望让不同 AI 助手分工完成任务，而不是反复切换聊天窗口，可以了解一下 DS Bot。

DS Bot 是什么？和 DeepSeek Harness 有什么区别？

DS Bot 是开发者 Fei2411 发布的开源多 AI Agent 协作工具，采用 Apache 2.0 许可证。项目基于 DeepSeek Harness（DSH）开发，但并非 DeepSeek 官方产品，也不代表与 DeepSeek 存在官方合作关系。

如果把 DSH 看作运行 AI Agent 的基础环境，那么 DS Bot 更像是一个团队管理工具：它增加了多 Bot 创建、独立记忆、群聊和任务委派等能力，让不同 AI 助手能够按角色协作。与偏向云端 AI 员工服务的 Grok Bot 不同，DS Bot 更侧重本地 Agent 的组织与管理。

安装方式也比较灵活。如果直接使用 DS Bot 桌面版，不需要额外安装 DSH，因为运行环境已经包含在内；如果想把它添加到现有的 DSH Desktop 或 DSH Web 中，则可以选择插件安装。

如果之前还没接触过 DeepSeek Harness，可以先看看本站的 DeepSeek Harness 桌面端介绍，了解它的基础功能，再看 DS Bot 增加了哪些多 Agent 协作能力。

多个 Bot 如何协作？

Chief：负责协调其他 AI 助手

打开 DS Bot 后，会先看到一个名为 Chief 的主 Bot。你可以直接和它对话，让它帮你创建其他 Bot，并根据不同任务安排角色。

比如，你想研究一个开源项目，可以让不同 Bot 分别负责资料搜集、功能分析和文档整理：

  • Research： 查找项目官网、GitHub 和技术文档。
  • Analyst： 整理核心功能，核对许可证和使用限制。
  • Writer： 根据收集到的资料整理成文章或文档。
  • Coder： 负责代码分析和开发相关任务。

这些 Bot 可以使用不同的模型，也有各自的记忆和工作目录。你可以让 Chief 根据任务安排成员，也可以直接在群聊中 @ 某个 Bot，让它处理指定工作。

需要注意的是，安装后默认只有 Chief，其他 Bot 需要自己创建。另外，Bot 的文件访问和命令执行权限仍由用户控制，Chief 可以协助管理团队，但不能自行修改成员的权限设置。

群聊、@ 委派和 Goal 目标管理

DS Bot 的群聊并非让几个模型无序地轮流回答。每个群聊可以指定管理员，默认由管理员先回应用户，再按需要调用其他 Bot；你也可以通过 @成员名称 直接指定某个 Bot。

Bot 之间能够互相委派工作，接到任务的成员独立处理后，把结果发回群聊。需要多阶段推进时，还能使用 Goal：管理员先确认完成标准，再分配阶段任务并逐步检查结果。

举个流程示例：如果要整理一款开源工具，Research 可以搜集项目文档，Analyst 核对许可证和部署条件，Writer 整理文章，最后由 Chief 汇总待核实事项。这样做的价值在于分工和交接，而不在于简单增加聊天人数。

群聊还可以引用其他对话作为上下文。但每增加一次成员调用，就可能产生新的模型请求；多 Bot 协作通常比单 Bot 问答消耗更多 Token，不适合所有日常提问。

独立记忆、工作目录与 Private Bot

每个 Bot 可以设置自己的角色、模型、记忆和工作目录。群聊也有独立的记忆与工作目录，方便持续处理同一类任务。

如果有不希望团队其他成员读取的内容，可以启用 Private Bot。其他 Bot 不能直接读取它的文件夹、记忆和聊天记录，向外分享内容还需要用户批准。不过，Private Bot 不能担任主 Bot，也不能加入群聊。

Private Bot 不是操作系统级沙箱。 如果你允许它执行终端命令或联网，它仍可能访问系统文件、连接外部服务；使用云端模型时，相关对话也仍需交由模型服务商处理。

接入现有 Claude Code、Codex 和 Cursor CLI

DS Bot 支持将电脑上已经安装的 Claude Code、Codex CLI、Cursor CLI、Devin CLI、OpenCode、Gemini CLI 等编程 Agent 作为团队成员。新建 Bot 时选择本地 Agent，便可以在 DS Bot 中与其对话，或让它参与群聊和任务交接。

需要区分两套运行方式：普通 Bot 使用 DSH 配置的模型；本地 CLI Agent 则使用对应 CLI 自己的登录、套餐、工具和上下文，不会自动继承 DS Bot 的所有 MCP 连接器与共享能力。部分自定义 CLI 如果不支持 HTTP MCP，也无法使用创建成员、委派任务等团队工具。

Cursor CLI 还有一个实际使用细节：在 DS Bot 中为 Cursor Bot 选择某个具体模型，可能改变 Cursor CLI 保存的全局默认模型。如果不想影响终端里其他 Cursor 实例，建议保留“CLI 默认”选项。

DS Bot 支持哪些工具？浏览器、电脑操控与第三方应用

浏览器操作： 每个 Bot 可以使用独立的浏览器登录环境。发帖、上传、下载、删除等操作需要用户批准；登录、验证码、付款等环节也可以交还给用户处理。浏览器操控适用于独立桌面版和 DSH Desktop，不适用于 DSH Web。

电脑操控： 可以分别设置只查看（View Only）、后台操作（Background）和前台操作（Foreground），并限定允许使用的应用。macOS 需要 14 或更新版本及相应的辅助功能、屏幕录制权限；Linux 支持 X11，Wayland 支持有限。所有 Bot 共用同一个桌面，同一时间不能同时操作同一个前台鼠标或应用。

聊天软件： 可连接微信、飞书、钉钉、企业微信、QQ、Telegram、Discord 和 Slack，用消息向 Bot 发任务或处理审批。具体能力取决于平台，例如微信仅支持与扫码配对账号的私聊，不支持微信群聊；电脑必须保持唤醒且 DS Bot 正在运行，消息才能持续收发。

连接器与办公文件： 项目支持 GitHub、Gmail、部分邮箱及远程 MCP 服务，还能导入 Claude Desktop、Cursor、VS Code 的配置。邮件默认经过用户确认后才发送。Bot 也可以创建、检查和编辑 Word、PowerPoint、Excel 文档；桌面版具备完整运行环境，而 DSH Web 在从零创建文档和页面渲染方面存在限制。

此外，Bot 支持定时任务，Usage 页面可查看按 Bot、模型及时间划分的 Token 使用量。

DS Bot 怎么安装？桌面版、插件和 Docker 如何选择？

DS Bot 提供三种使用方式：独立桌面应用、DSH 插件和 Docker。选哪一种，主要看你准备在哪里运行它。

安装方式 适合场景 需要注意
独立桌面版 Windows、macOS、Linux 个人用户 已内置 DSH，配置模型即可使用
DSH Desktop 插件 已经安装 DSH Desktop 的用户 需要提前配置至少一个模型
DSH Web 插件 已有 DSH Web 环境的用户 需要 Node.js 22.19+ 和 pnpm，不支持桌面版浏览器操作
Docker NAS、Linux 服务器及常开设备 Docker 24+、Compose v2.24+，目前只有 Full Access 权限模式

普通用户：直接下载桌面版

如果只是想体验 DS Bot，直接下载独立桌面版就可以，不需要先安装 DeepSeek Harness。

前往 GitHub Releases，根据系统下载 Windows、macOS 或 Linux 安装包。首次启动后，在 Settings 中配置模型，就可以开始创建和使用 Bot。如果之前已经在 DSH 中配置过团队，也可以直接复制原有配置。

Windows 或 macOS 首次打开时可能遇到未签名应用的安全提示。确认安装包来自项目官方 Release 后，再根据系统提示允许打开。

已经安装 DSH：直接添加插件

如果电脑上已经运行 DeepSeek Harness，可以直接安装 DS Bot 插件，不必再下载独立桌面版。

  • DSH Desktop： 打开侧边栏的「插件」→「添加插件」，输入 ds-bot，安装后点击「立即启用」。中国大陆网络环境可以选择官方提供的中国大陆镜像源。
  • DSH Web： 需要先安装 Node.js 22.19 或以上版本及 pnpm，然后执行项目 README 提供的安装命令：
npx @deepseek-ai/dsh@0.2.2-rc.1 plugin --profile web add ds-bot
npx @deepseek-ai/dsh@0.2.2-rc.1 web

这里使用的是项目当前文档中的 DSH 版本。需要注意，DSH Web 并不包含桌面版的浏览器操作能力，如果需要使用完整的桌面功能，优先选择独立桌面版或 DSH Desktop。

安装细节可以参考 DS Bot 官方中文 README。

NAS 和 Linux 服务器：使用 Docker 部署

如果希望 DS Bot 长期运行在 NAS 或 Linux 服务器上，可以使用 Docker。官方方案实际上是将 DSH Web 和 DS Bot 插件一起打包到容器中，不需要再单独安装 DSH。

部署前需要准备：

  • Docker 24+，Docker Compose v2.24+
  • Linux x86-64 环境
  • DeepSeek API Key，或者兼容 Anthropic Messages API 的模型接口

ARM64 架构也有可能运行，但官方尚未完成测试，不能视为已经验证兼容。

基本部署步骤：

从 GitHub 克隆项目：

git clone https://github.com/Fei2411/DS-Bot.git
cd DS-Bot

修改仓库根目录的 docker-compose.yml，填写模型 API Key、NAS 地址以及文件属主对应的 PUID / PGID，然后启动：

docker compose up -d --build
docker compose logs ds-bot

容器启动后，可以在日志中找到首次登录所需的 Token。根据日志提示，访问：

http://NAS_IP:13080/?token=日志中的Token

完成首次登录后，通常可以直接通过 http://NAS_IP:13080/ 打开 DS Bot。

注意端口不要弄混： 项目提供了两套 Compose 配置：

  • 仓库根目录的 docker-compose.yml：默认使用宿主机 13080 端口，数据保存在 docker/data 和 docker/workspace。
  • docker/ 目录下的 compose.yml：通过 .env 配置，默认使用 3080 端口。

两种部署方式选一种即可，不要同时运行并指向同一份数据目录。

Docker 部署需要特别注意权限和安全

Docker 版有一个比较重要的限制：目前只提供 Full Access 权限模式。

这意味着 Bot 执行命令时不会像桌面版那样逐项请求批准，容器本身就是主要的隔离边界。因此，部署时不要把宿主机的整个文件系统或包含敏感数据的目录挂载进去，只开放 Bot 实际需要使用的工作目录。

另外还有两个细节：

  • DSH_TRUSTED_HOST 需要填写允许访问的 NAS IP 或域名，不包含端口，否则可能出现 403 错误。
  • 官方建议通过反向代理启用 HTTPS。虽然当前版本支持通过局域网 HTTP 访问，但输入的 API Key 和其他敏感信息会以明文形式经过局域网，不适合长期作为安全访问方式。

如果准备在 NAS 或服务器上长期使用，建议先把网络访问、目录挂载和权限范围配置好，再导入实际工作资料。

完整配置和更新方法可以参考 DS Bot Docker 官方部署文档。

DS Bot 免费吗？多个 AI Bot 会增加多少成本？

DS Bot 本身是免费的 Apache 2.0 开源软件，但使用 AI 模型并不是完全免费的。通过 API 接入模型，需要按照对应服务商的价格支付费用；如果使用 Claude Code、Codex 等本地 CLI，则消耗各自账户的套餐额度或订阅权益。

需要注意的是，Bot 数量增加，模型调用量也可能随之增加。 比如你让 Chief 安排 Research 搜集资料，再交给 Writer 整理文章，中间每个 Bot 都可能产生额外的模型请求。如果还让多个 Bot 在群聊中反复讨论，Token 消耗会更明显。

DS Bot 自带 Usage 用量统计，可以按 Bot、模型和时间查看 Token 使用情况，方便找出哪些成员调用比较频繁。不过，这里显示的是 Token 用量，不是模型服务商最终的账单金额，实际费用还要以对应平台的用量记录为准。

刚开始使用时，不必一次创建太多 Bot。先用 Chief + 1～2 个专业 Bot 处理实际任务，看看分工是否能减少重复操作，再根据需要增加成员。毕竟，多个 AI 助手能不能提高效率，比单纯增加 Bot 数量更重要。

DS Bot 的数据安全吗？本地保存和权限管理需要注意什么？

DS Bot 支持将 Bot 记忆、聊天记录和工作文件保存在自己的电脑或服务器上。不过，数据保存在本地，并不代表 AI 对话完全不会发送到云端。

例如，使用 DeepSeek、Claude 等云端模型时，Bot 仍然需要将任务内容和必要的上下文发送给对应的模型服务商进行处理。本地保存主要解决的是数据文件存放在哪里的问题，并不等于完全离线运行。

不同安装方式的数据目录也有所区别：

  • 独立桌面版： 默认保存在 ~/.ds-bot。
  • DSH 插件版： 使用 ~/.dsh 下的 bot/、sessions/ 等目录。
  • Docker 版： 数据保存在配置的宿主机挂载目录中。

另外，卸载 DS Bot 或删除插件不会自动清除这些数据。如果准备重新安装或迁移设备，记得提前检查和备份相关目录。

权限管理同样值得注意。DS Bot 可以为不同 Bot 设置只读、工作目录访问或完全访问等权限预设，具体权限由用户在设置中控制，Bot 不能自行修改。

如果只是让 Bot 整理资料，通常没有必要开放整个电脑的文件访问权限。建议只提供任务需要的文件夹，并谨慎配置 GitHub、邮箱等外部连接器。涉及邮件发送、文件删除和内容发布等操作时，尽量保留人工确认。

如果部署 Docker 版本，还需要格外留意： 官方目前只提供 Full Access 权限模式，容器是主要的隔离边界。不要随意挂载宿主机的重要目录，也不要把包含密码、密钥和私人文件的目录直接开放给 Bot。

DS Bot 支持手机远程管理吗？Android 伴侣 App 怎么用？

除了电脑端，DS Bot 还提供了一个 Android 手机伴侣 App（目前处于 Beta 阶段）。配对之后，即使不在电脑旁边，也可以通过手机和 Bot 对话、查看团队成员、管理记忆与定时任务，还能处理 Bot 发来的问题和操作审批。

连接方式也比较简单：在电脑端打开 Settings → Phone，使用手机扫描二维码完成配对。手机和电脑之间通过 Relay Server 建立端到端加密连接，不需要为电脑单独开放公网端口。

不过，这并不意味着 DS Bot 已经变成了可以独立运行的云端 AI 服务。手机只是远程操作入口，真正执行任务的仍然是电脑端的 DS Bot。 如果电脑关机、进入睡眠或应用退出，手机端也无法继续让 Bot 执行任务。

Android 安装包可以从 DS Bot GitHub Releases 获取。由于目前仍处于 Beta 阶段，安装前建议查看最新版本说明。

DS Bot 适合哪些人？

如果只是让一个 AI 回答问题、整理文本，普通聊天客户端通常更简单。DS Bot 主要适合已经把工作拆分成多个角色、需要长期记忆或任务交接的人：例如使用 Claude Code 与 Codex 的开发者、需要研究与写作分工的内容团队，以及希望在 NAS 上运行 Agent 工作环境的自托管用户。

它的价值是统一组织多个 Agent，而不是让模型突然变得更聪明。相应地，你需要接受更多配置工作、模型调用开销，以及权限与数据管理责任。

DS Bot 与其他 AI Agent 工具有哪些区别？

虽然这些工具都能让 AI 执行任务，但它们解决的问题并不完全相同。Muse 和 Grok Bot 偏向云端服务，OpenClaw 和 Hermes Agent 更强调用户自己管理 Agent 运行环境，而 DS Bot 主要用于组织多个 AI 助手协同工作。

除了功能，选择时还需要考虑运行环境、订阅费用，以及模型调用和服务器成本。

工具 核心定位与运行方式 费用模式 适合场景
Muse（Meta） 云端个人 AI 助手，通过独立云端虚拟机处理邮件、日程和网页任务 基础功能免费，高级功能提供付费订阅 个人事务管理，不想自行部署
Grok Bot 云端 AI 员工团队，Bot 可使用云端电脑执行任务，支持多 Bot 协作、跨应用操作和持续运行。 个人付费套餐 $30/月起，包含使用额度，超额使用可能产生额外费用 需要多个 Agent 持续处理跨应用任务
OpenClaw 自托管 AI 助手，通过 Gateway 连接聊天平台、工具和自动化流程 软件免费开源（MIT），模型 API、服务器等费用另计 自建 AI 助手、消息平台接入和自动化
Hermes Agent 开源 AI Agent，支持长期记忆、Skills、工具执行和多渠道接入 软件免费开源（MIT），可使用自己的模型 API 或付费 Nous Portal 长期运行的个人 Agent、技能积累和任务自动化
DS Bot 开源多 Agent 协作工具，通过 Chief、群聊和任务委派协调不同 AI 助手 软件免费开源（Apache-2.0），模型 API 或外部 CLI 套餐费用另计 多个 AI Agent 分工、Claude Code / Codex 协作与自托管

费用说明：以上为截至 2026 年 11 月 17 日核对的官方收费模式。Grok Bot 价格以官网个人月付套餐为参考。实际费用还可能受到使用额度、模型、服务器及第三方服务影响，订阅和额度请以各项目官网为准。

如果主要是管理个人邮件、日程等事务，Muse 更接近开箱即用的个人 AI 助手。如果希望多个 Agent 在云端持续运行，并使用浏览器和不同应用完成任务，可以考虑 Grok Bot。

如果更看重自托管和自主配置，OpenClaw 适合搭建连接消息平台与工具的 AI 助手；Hermes Agent 则更强调长期记忆、技能积累和持续执行任务。这两款工具也支持多 Agent 或任务委派能力，并非只能使用单个助手。

DS Bot 的侧重点不同：它把多个拥有独立角色、模型和工作目录的 Bot 组织起来，通过 Chief、群聊和任务委派协作，还能接入已有的 Claude Code、Codex CLI、Cursor CLI 等本地编程 Agent。

因此，如果你已经在使用多个 AI 编程助手，希望减少手动分配任务和整理结果的工作，DS Bot 更值得关注。如果平时主要是和单个 AI 助手对话，就不一定需要专门部署一套多 Agent 协作系统。
