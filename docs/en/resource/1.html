Clearcam：给普通监控摄像头加上本地 AI 的开源 NVR

Published 2026-10-28

已经装好的监控摄像头，如果只会录像和回放，想再加上人车识别、目标追踪或者录像搜索，往往要换摄像头、换 NVR，或者接入厂商自己的云服务。

Clearcam 是一个可以自己部署的开源 NVR。它直接读取现有 RTSP 摄像头的视频流，在本地电脑上做 AI 目标检测、追踪和录像搜索，不需要为了这些功能重新换一套监控设备。

如果家里或办公室已经有 IP 摄像头、旧 NVR，或者正好有一台闲置电脑、家庭服务器，Clearcam 就比较值得折腾。原来的摄像头可以继续用，AI 分析放到自己的设备上跑，也能少依赖厂商提供的云端功能。

项目官网：Clearcam

GitHub：roryclear/clearcam

Clearcam 是什么？给 RTSP 摄像头增加本地 AI 的开源 NVR

NVR 主要负责接收 IP 摄像头的视频流、保存录像，再提供实时查看和回放。Clearcam 在这些基础功能上又加了一层 AI 分析。

除了录像和回放，Clearcam 还加入了这些能力：

  • AI 目标检测；
  • 目标追踪；
  • 监控录像搜索；
  • 移动端事件通知；
  • 远程查看实时摄像头；
  • 远程查看事件录像；
  • AI 通知摘要。

Clearcam 现在已经支持基于 Qwen3 VL 的 AI 通知摘要，也加入了相似图片搜索和上传图片搜索。相比普通 NVR 主要靠时间轴回看录像，它多了一层对监控事件的识别和检索能力，后面找人、找车或者回溯某段画面会方便不少。

截至 2026 年 10 月，Clearcam 在 GitHub 上约有 2.1k Stars、206 Forks，项目采用 GPL-3.0 开源许可证。

GPL-3.0 主要覆盖公开代码，官方 Premium 云服务和移动端相关功能仍以 Clearcam 自己的服务条款为准。

哪些摄像头可以接入 Clearcam？RTSP 是关键

Clearcam 对摄像头最重要的要求是 RTSP。

只要摄像头能够提供 RTSP 视频流，而且运行 Clearcam 的电脑能够正常访问摄像头，就可以把视频接进来。

这类方式比较适合标准 IP Camera、支持 RTSP 的家用摄像头，以及已经搭好的网络监控系统。原来的摄像头继续负责拍摄，Clearcam 再从视频流里做 AI 分析。

如果摄像头完全依赖厂商私有协议，只能通过官方 App 查看，又没有开放 RTSP，就不能直接按这种方式接入。

如果以后有自己搭 NVR 的打算，买摄像头时除了分辨率、夜视和硬件 AI，RTSP 这类开放接口也值得提前确认。它会直接影响后面能不能接 Frigate、Clearcam 这类自托管监控软件。

本地 AI 能做什么？目标检测、追踪和录像搜索

1. 检测和追踪监控画面中的目标

Clearcam 会对摄像头视频进行 AI 推理，用来识别并持续追踪画面中的目标。

像有人进入监控区域、车辆经过，或者需要持续跟踪某个目标，都属于它要处理的场景。

这和传统运动检测不太一样。普通运动检测只知道“画面动了”，AI 检测则会进一步判断画面里出现了什么，后续通知也可以更有针对性。

2. 搜索以前的监控录像

录像搜索是 Clearcam 比较实用的一项功能。

传统 NVR 找录像大多还是靠时间轴：先记住大概几点发生，再一段一段往回翻。Clearcam 已经加入相似图片搜索和上传图片搜索，可以根据图像去找以前出现过的目标。

比如手里有一张车辆截图，就可以尝试从历史记录里找相似画面。对于录像比较多的监控环境，这会比单纯拖时间轴省事很多。

3. AI 通知摘要

Clearcam 还加入了基于 Qwen3 VL 的 AI Notification Summaries。

除了告诉你“检测到人物”之外，它还可以进一步分析事件画面，再生成一段摘要信息。

这类功能会比普通目标检测更吃算力，实际速度也会受到 GPU、模型大小和运行设备影响。

Clearcam 是完全本地运行的吗？

Clearcam 的 NVR 和 AI 推理可以直接跑在自己的电脑上，但不是所有功能都完全离线。

平时接收 RTSP 视频流、做目标检测和处理录像，可以放在本地完成。人在外面查看实时画面、接收官方移动端通知或者远程打开事件录像，则属于 Premium 功能，会用到 Clearcam 的服务器和云存储。

项目说明 Premium 数据使用端到端加密，不过远程服务本身仍然有云端参与。

如果不想走官方通知链路，也可以修改通知 URL，自己接 Home Assistant、Pushover 或 n8n。AI 检测继续在本地跑，通知这一层可以按照自己的环境来搭。

Clearcam 怎么安装？Python、FFmpeg 与 Docker 支持

Clearcam 现在直接跑 Python 项目，不是像很多自托管工具那样拿一份 Docker Compose 就能启动。

电脑需要有 Python 3.11 以上版本和 FFmpeg，推理部分基于 tinygrad。现在主要还是 Mac 和 Linux 用起来比较顺，Windows 这边还有 FFmpeg 兼容问题。

启动流程倒不复杂：先装 requirements.txt 里的依赖，再运行 clearcam.py，之后用浏览器打开本机 8080 端口进入界面。

如果电脑有 AMD 或 NVIDIA GPU，也可以通过项目提供的 DEV 参数指定设备，避免推理全部压在 CPU 上。

Clearcam 目前还没有把 Docker Compose 做成官方标准部署方式。对于习惯在 NAS、Proxmox 或 Ubuntu Server 上统一用 Docker 管服务的人来说，安装、升级和迁移都会多一些手工操作。

Clearcam vs Frigate：两款开源 AI NVR 怎么选

如果准备自己搭一套开源 NVR，Frigate 基本都会被拿来比较。Clearcam 官网也专门解释过为什么还要再做一个类似项目，它想把配置做得简单一些，同时直接利用电脑现有的 GPU。

两者现在所处的阶段并不一样。

Frigate 已经发展成一套比较完整的本地 AI NVR，Docker、Home Assistant、多摄像头管理和各种硬件加速方案都比较齐。Clearcam 还在快速更新，重点则放在把现有 RTSP 摄像头接进来，再增加检测、追踪和录像搜索。

对比 Clearcam Frigate
安装 目前主要直接运行 Python 以 Docker Compose 为主
AI 检测 支持本地目标检测和追踪 支持本地目标检测，配置体系更完整
录像搜索 支持相似图片和上传图片搜索 支持 Semantic Search
Home Assistant 可通过通知 URL 等方式接入 有正式集成
硬件加速 目前重点支持 AMD / NVIDIA GPU 支持的硬件和加速器更多
项目成熟度 仍在快速更新 文档、社区和部署方案更完整

Frigate 对硬件的适配范围更广，Intel、AMD、NVIDIA、Hailo、Rockchip 等平台都有对应方案。如果家里已经跑着 Home Assistant，或者本来就习惯用 Docker 管服务，接进现有环境会更方便。

录像搜索这块，两边现在也都有自己的做法。Clearcam 支持相似图片和上传图片搜索；Frigate 的 Semantic Search 则可以根据文字或图片查找历史事件。

所以现在真正拉开差距的，不是谁有没有 AI 搜索，而是部署方式、硬件适配和整个生态。

如果只是想给现有 RTSP 摄像头加一层 AI，Clearcam 比较直接；如果准备长期搭一套完整的家庭 AI NVR，Frigate 的配套会更齐。

Clearcam 当前有哪些限制？

Windows 目前还有 FFmpeg 兼容问题，Mac 和 Linux 会更省事。

部署方式仍然以 Python 项目为主，没有官方 Docker Compose。对于习惯用 NAS、Proxmox 或 Docker 管理服务的人来说，后续维护会多一点手工操作。

另外，官方远程查看和移动通知属于 Premium 功能，会用到 Clearcam 的服务器和云存储。Home Assistant、硬件加速器和社区资料方面，目前也没有 Frigate 那么丰富。

现有 NVR 需要换掉吗？Clearcam 更适合怎么用

如果家里或办公室已经有支持 RTSP 的摄像头，其实没必要为了试 Clearcam 把原来的监控系统拆掉。

官网 FAQ 专门提到，已经在使用 Hik-Connect 的情况下，可以同时运行 Clearcam。原来的摄像头和 NVR 继续负责录像，Clearcam 再读取 RTSP 视频流，用来做人车检测、目标追踪和录像搜索。

这样对现有设备改动比较小。手里正好有 Mac、Linux 主机或者家庭服务器，就可以先把 AI 这一层加上去，不影响原来的录像链路。

如果以后想把整套监控系统都迁到自托管环境，再根据 Docker、Home Assistant、硬件加速和多摄像头管理这些需求决定要不要换成 Frigate。

常见问题

Clearcam 是免费的吗？

基础软件可以免费运行。官方移动端的远程查看和通知属于 Premium 功能，这部分会使用 Clearcam 的服务器和云存储。

Clearcam 支持哪些摄像头？

最关键的是摄像头能够提供 RTSP 视频流，并且 Clearcam 主机可以正常访问它。没有开放 RTSP、完全依赖厂商私有 App 的摄像头，就不能直接按这种方式接入。

Clearcam 支持 Docker 吗？

目前主要还是通过 Python 源码运行，没有把 Docker Compose 作为官方标准部署方式。如果准备放在 NAS 或家庭服务器上长期跑，这一点需要提前考虑。

Clearcam 支持 Windows 吗？

Windows 目前主要还有 FFmpeg 兼容问题。Mac 和 Linux 会简单一些，Windows 用户则可能需要自己处理环境问题。

Clearcam 和 Frigate 哪个更适合？

如果只是想给现有 RTSP 摄像头增加 AI 检测、追踪和录像搜索，Clearcam 上手思路比较直接。

如果已经有 Home Assistant、Docker 环境，或者需要更广的硬件加速支持、多摄像头管理和长期维护，Frigate 的配套会更完整。

Clearcam 的监控视频会上传云端吗？

本地 NVR 和 AI 推理可以在自己的设备上完成。使用官方 Premium 的远程查看、事件录像和移动通知时，则会用到 Clearcam 的服务器和云存储。
