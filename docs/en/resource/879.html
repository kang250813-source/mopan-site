FreeCut：开源浏览器视频编辑器，免安装本地剪辑不上传素材

Published 2026-03-24

想剪一段视频，但不想装 Premiere 或 DaVinci，也不想把素材传到第三方平台，这类需求其实比想象中常见。FreeCut 是一款运行在浏览器里的浏览器视频编辑器，支持多轨道时间线、关键帧、WebGPU 特效和本地 Whisper 转录。它更吸引人的地方，不是团队协作，而是免安装、少上传、打开网页就能直接剪。它底层依赖 WebGPU、WebCodecs 和 OPFS 这些现代浏览器能力，连最后的视频导出也主要在本地完成。

这款浏览器视频编辑器适合什么人

先说结论，FreeCut 不是那种“只能裁一刀、拼几段”的网页小工具。它更像一款把浏览器能力吃得比较深的多轨道编辑器，适合几类用户：不想装重型客户端的内容创作者、经常在不同设备之间切换的轻办公用户、对素材流向比较敏感的小团队，以及想尽量减少 SaaS 订阅和外部上传环节的人。

它不太适合什么场景也要说清楚。要是你的需求是复杂影视级调色、超重型多机位工程、成熟插件生态，或者要在 Safari、Firefox 这类浏览器里稳定跑，那 FreeCut 目前并不是最稳妥的主力方案。目前它的硬性门槛是 Chrome 113+，因为底层几个关键 API 在其他浏览器里还没完整实装。

 

浏览器视频编辑器能做到什么程度

FreeCut 的时间线能力比很多人预期要完整。它支持视频、音频、文字、图片甚至图形的多轨混剪，带轨道分组、静音、可见、锁定联动，也有 Trim、Split、Join、Ripple Delete、Rate Stretch、Rolling Edit、Slip、Slide 这些常见的精剪工具。对于一款浏览器工具来说，这已经不是“玩具级”配置。

多轨时间线和精剪工具

对日常做短视频、课程切片、产品演示、会议片段整理的人来说，真正有用的不是参数多，而是时间线够不够顺手。FreeCut 在这点上至少把基本盘搭起来了。它有 Source Monitor、Mark In/Out、Insert/Overwrite，也有波形、胶片缩略图和 Marker 标记。你要做一条信息密度不低的视频，不至于刚进来就发现工具不够用。

WebGPU 特效和关键帧

它的视觉特效主要走 WebGPU。自带的能力包括模糊、调色、扭曲、风格化、抠像，以及 25 种 GPU 加速混合模式；关键帧部分则支持贝塞尔曲线、spring 缓动、Graph Editor、Dopesheet 和 Auto-keyframe。换句话说，FreeCut 不是只能做“拼接 + 导出”，而是能覆盖一部分常见的短视频包装需求。

本地 Whisper 字幕

它还有一个比较容易打到痛点的功能：浏览器内的本地语音转文字。它的 Whisper 模型直接跑在本地的 Web Worker 里，支持多语言，并能把转录结果直接生成字幕条目。这个设计的意义不只是方便，还在于能减少把音频再交给外部服务处理的环节，对看重成本和素材流向的人会更有吸引力。

素材去哪了：它和多数在线剪辑工具的核心区别

FreeCut 最有辨识度的地方，不是“能在浏览器里剪视频”，而是它把大部分处理链路留在了本地。它的导入机制有点意思：通过 File System Access API 引用本地文件，而不是先复制到远端；导出则通过 WebCodecs 在浏览器内完成，不依赖服务器渲染。此外，它还用 OPFS 生成预览代理、用 IndexedDB 做持久化，并支持把项目打包成 ZIP 导出。

✅ 核心数据流向拆解

  • 素材导入：通过 File System Access API 引用本地文件
  • 预览代理：生成在 OPFS 虚拟文件系统
  • 字幕转录：Whisper 在 Web Worker 本地离线运行
  • 导出渲染：通过 WebCodecs 在浏览器侧完成
  • 项目保存：IndexedDB 持久化，支持 ZIP 项目包导入导出

这并不代表你可以把它理解成绝对安全方案，但至少能看出一点：和依赖上传素材、云端渲染的在线产品相比，FreeCut 更适合那些希望减少外部传输环节的人。对企业内部素材、培训视频、会议片段、敏感演示录屏这类内容来说，这种本地优先的思路是有实际意义的。

FreeCut 支持哪些格式，够不够日常使用

格式兼容性上，FreeCut 支持 MP4、WebM、MOV、MKV 这些常见视频容器，视频编码包括 H.264、H.265、VP8、VP9、AV1，音频支持 AAC、Opus、MP3、FLAC、PCM；质量预设从 2 Mbps 到 20 Mbps。对大多数网页视频、课程剪辑、产品演示和社媒内容来说，这套规格已经覆盖了主流需求。

📌 规格与参数边界

  • 视频容器：MP4、WebM、MOV、MKV
  • 视频 / 音频编码：H.264、H.265、AV1 / AAC、Opus、MP3 等
  • 单文件上限：最高支持 5 GB
  • 字幕转录：本地 Whisper，支持多模型与多语言
  • 开源协议：MIT，商业使用前仍建议自行复核条款

注：上述信息基于项目当前发布版本整理，API 支持情况与规格上限可能随后续迭代调整。

本地部署并不复杂，但要接受它的边界

如果你不只是想直接用官网，而是想自己跑起来，FreeCut 的本地启动门槛并不高。只要有 Node.js 18+ 环境，敲几行 npm install 和 npm run dev 就能在本地启动。这也解释了为什么我不太建议把它硬写成“自托管平台”。它本质上是一个前端项目，普通用户真正会在意的，还是“免安装、直接可用、素材主要留在本地”这几个点。

git clone https://github.com/walterlow/freecut.git
cd freecut
npm install
npm run dev

使用前要注意的几个坑

⚠️ 准备上手前建议先看

  • 浏览器要求明确：目前更适合在 Chrome 113+ 及兼容的 Chromium 环境中使用，部分浏览器可能需要额外配置。
  • Brave 需要手动开权限：如果你用 Brave，默认关闭了 File System Access API，需到 brave://flags/#file-system-access-api 开启后重启。
  • 超大素材需规划：目前存在 5 GB 的单文件上限。
  • 嵌套合成有边界：当前版本的 Pre-compositions 仅支持 1 层嵌套。

还有一点要说透：FreeCut 虽然省去了安装和上传，但多轨剪辑、大分辨率素材、复杂特效和本地转录，最后还是会吃你自己的 CPU、GPU、内存和显存。这对轻量剪辑是好事，但老旧轻薄本在处理多轨 4K 时照样可能遇到性能瓶颈。这类性能限制，本质上还是绕不过去。

和同类工具相比，FreeCut 适合什么场景

FreeCut 的优势不在于海量的现成模板，也不在于云端协作，而是在浏览器里尽量把剪辑、转录和导出留在本地完成。对不想安装重型软件、又不想把素材交给第三方平台处理的人来说，这种思路很有吸引力。

如果你平时极度依赖团队审片流、云端素材库，那 FreeCut 未必是最省心的选择。它更适合另一类需求：临时剪一条视频、处理课程录屏、整理会议片段、做轻量演示内容，或者单纯希望把素材尽量留在自己设备里。

换句话说，FreeCut 不是一款试图覆盖所有场景的全能型产品，而是一款方向很明确的浏览器视频编辑器。要不要长期当主力工具，还得看你的硬件性能，以及项目复杂度是不是落在它更擅长的范围内。

常见问题

FreeCut 完全免费吗？

采用 MIT 许可证开源，官网可直接使用。如需商业环境使用，建议自行核对协议条款。

素材会上传到服务器吗？

按目前的设计，它通过引用本地文件进行操作，渲染和导出主要在浏览器本地完成，不依赖外部服务器来处理视频素材。

可以在 Firefox 或 Safari 上用吗？

目前更适合在 Chrome 113+ 及兼容的 Chromium 环境中使用，Firefox 和 Safari 暂时不适合作为主力环境。

能自己部署吗？

可以。克隆源码后即可本地运行，也可以构建静态产物部署到自己的服务器上。
