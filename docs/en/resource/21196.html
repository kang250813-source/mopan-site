Free Claude Code：给 Claude Code、Codex 接入 Ollama 和第三方模型

Published 2026-09-01

习惯用 Claude Code、Codex 写代码，又想接 Ollama、DeepSeek、Gemini 这些模型，可以看看 Free Claude Code。它在客户端和模型之间加了一层本地代理，不用换掉原来的 Coding Agent，就能切换不同的云端或本地模型。

Free Claude Code（简称 FCC）和 Anthropic 没有关联，也不是绕过 Claude 官方额度的工具。它负责把 Claude Code、Codex 等客户端发出的请求，转给你自己配置的模型 Provider，例如 Gemini、DeepSeek、Groq、OpenRouter，或者本地运行的 Ollama。

Free Claude Code 能拿来做什么

Free Claude Code 可以让 Claude Code、Codex 这些 AI 编程工具继续按原来的方式使用，但把实际调用的模型换成你自己配置的服务。比如可以接本地 Ollama，也可以接 OpenRouter、DeepSeek、Gemini 等云端 API。

如果同时用了多个模型或 Provider，也可以在 Free Claude Code 里统一切换和管理，不用每换一个模型就重新改 Claude Code、Codex 的配置。

Free Claude Code 接入 Ollama、OpenRouter 和其他模型

想跑本地模型，可以接 Ollama、LM Studio 或 llama.cpp；使用云端 API，则可以配置 OpenRouter、DeepSeek、Gemini、Groq 等 Provider。Claude Code、Codex 还是原来的使用方式，请求由 Free Claude Code 转到你配置好的模型。

使用场景 怎么接 需要注意
Claude Code + Ollama 在 Free Claude Code 中配置 Ollama 服务地址和模型 本地模型最好支持 Tool Calling，并有足够的上下文长度；能正常连接，不代表复杂 Agent 任务的效果会和 Claude 原生模型一样
Claude Code + OpenRouter 配置 OpenRouter API Key，再在 Free Claude Code 中选择模型 可用模型、免费额度和限速取决于 OpenRouter 当前的模型目录和账号权限
Codex + DeepSeek / Gemini 配置对应的 Provider 和模型 不同模型对 Tool Calling、上下文和推理能力的支持并不完全一样
多 Provider Fallback 提前配置模型优先级列表 当前模型请求失败并完成重试后，再按顺序尝试后面的模型

项目当前支持 10 个 Coding Agent，包括 Claude Code、Codex、Cline、Aider 等；Provider 约 50 个，既有 OpenRouter、DeepSeek、Gemini 这类云端服务，也支持 Ollama、LM Studio、llama.cpp 等本地模型服务。

关于每月有 13 亿+ 免费 Token。这个不是 Anthropic 给 Claude Code 的额度，而是Free Claude Code把不同 Provider 的免费额度汇总在一起的意思。各家的免费模型、限速和额度都会调整，实际能用多少还是看具体 Provider。

Fallback 和模型路由有什么用

Fallback 可以理解成备用模型列表。你可以提前给多个模型排好顺序，当前模型请求失败并完成重试后，Free Claude Code 会继续尝试列表里的下一个模型，不需要重新开始当前任务。

Claude Code 里的不同模型入口也可以分别设置路由。支持为 Fable、Opus、Sonnet 和 Haiku 指定不同的兼容模型，例如把 Haiku 入口配置到一个模型，把 Opus 入口配置到另一个模型。这里改变的是后端路由，并不会让第三方模型变成 Claude Opus、Sonnet 或 Haiku。

直接改 Base URL 不行吗？

如果你只打算让 Claude Code 固定使用一个兼容 API，直接修改 Base URL 确实更简单，没必要为了这一件事再装一层代理。

Free Claude Code 的区别在于，它把多个 Provider、模型目录、Fallback 和不同 Coding Agent 的配置放到了一起。比如你同时在用 Claude Code、Codex，又有 OpenRouter、DeepSeek 和本地 Ollama，Free Claude Code 可以让这些客户端共用一套模型配置，而不是每个工具分别改环境变量和配置文件。

所以它更像一个给 Coding Agent 用的模型路由层，而不只是“让 Claude Code 换个模型”的工具。只固定使用一个模型的人，直接改 Base URL 反而更省事。

Free Claude Code 怎么安装，代码会发到哪里

macOS 和 Linux 可以运行项目提供的安装脚本，Windows 则使用 PowerShell 安装。装好以后会运行本地代理服务，并提供 Admin UI，用来配置 Provider、API Key、模型和 Fallback。

配置完成后，可以通过 fcc-claude、fcc-codex 等启动器运行对应的 Coding Agent。平时还是在 Claude Code 或 Codex 里工作，只是模型请求会先经过 FCC。

代码最终会不会离开本机，取决于你配置的上游模型。接本地 Ollama、LM Studio 这类服务时，模型推理可以在自己的机器上完成；接 OpenRouter、Gemini、DeepSeek 等云端 Provider 时，请求会发送给对应服务商。FCC 是代理和路由层，本身不会替你对代码内容做脱敏。

Free Claude Code 更适合哪些使用场景

如果平时同时用 Claude Code、Codex、多个云端 API 和本地 Ollama，或者需要配置 Fallback，FCC 会比较方便。

如果只固定使用 Claude Code 和一个模型，也没有多 Provider 管理需求，那直接使用原来的配置通常更简单。

常见问题（FAQ）

Free Claude Code 是 Anthropic 官方项目吗？

不是。Free Claude Code 是独立开源项目，采用 MIT 协议，与 Anthropic 没有关联。

Free Claude Code 可以让 Claude Code 使用 Ollama 吗？

可以。Free Claude Code 支持接入 Ollama，也支持 LM Studio、llama.cpp 等本地模型服务。

接入第三方 Provider 时要注意什么？

模型请求会发送到你配置的服务商，免费额度、限速、数据处理和商用规则也按对应 Provider 的政策执行。
