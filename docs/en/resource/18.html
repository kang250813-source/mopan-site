OpenSurge for Mac：开源 Mac 网关工具，用 mihomo 实现透明代理

Published 2026-07-28

开源部署提醒：
本项目为 GitHub 上的 GPL-3.0 开源工具，主要用于管理网络规则和流量策略。它不内置、也不提供任何代理节点或测速服务，相关网络配置需要用户自行准备。

OpenSurge for Mac 目前仍属于开源社区项目，功能支持和稳定性会随着版本更新变化，实际使用前建议查看 GitHub 仓库中的最新说明。

OpenSurge for Mac 是一个开源的 macOS 网关工具，它可以让一台 Mac 承担局域网出口角色，并通过 mihomo 管理其他设备的网络策略。

很多家庭设备，比如 Apple TV、PS5、Switch 或智能电视，并不能直接安装代理客户端。如果想让这些设备使用不同的网络规则，通常需要额外配置软路由，或者依赖支持网关模式的商业软件。

OpenSurge for Mac 的做法是，把闲置 Mac 放在局域网中作为网络网关，通过 DHCP、DNS 和透明代理机制，让接入设备按照预设规则进行分流。

OpenSurge for Mac 是如何实现局域网代理的？

这个项目没有重新实现底层网络能力，而是组合了多个开源组件来完成 Mac 网关功能。

OpenSurge for Mac 使用 dnsmasq 负责局域网 DHCP 和 DNS 分发，并调用 mihomo（原 Clash Meta）作为代理策略引擎。同时结合 macOS 自带的 pf 防火墙和 IPv4 转发能力，让 Mac 承担局域网出口网关的角色。

在这种模式下，接入同一局域网的设备可以通过这台 Mac 获取网络配置，流量经过网关后再根据规则判断走直连或代理策略。对于 Apple TV、PS5 等无法直接安装客户端的设备，不需要额外部署代理程序即可使用统一的网络规则。

OpenSurge for Mac 可以解决哪些网络需求？

OpenSurge for Mac 的主要使用场景集中在多设备网络管理。当家庭或小型办公环境中存在 Apple TV、游戏主机、智能电视等无法直接安装客户端的设备时，可以通过一台 Mac 作为局域网网关，统一管理不同设备的网络策略。

相比单纯运行代理客户端，OpenSurge 更偏向于局域网出口管理，重点解决设备分流、网络状态查看以及已有 mihomo 配置复用等需求。

  • 按设备配置分流：
    它可以识别局域网中的不同设备，并为不同终端设置独立策略。例如手机、Apple TV、游戏主机等设备可以使用不同的代理规则，避免所有设备共享同一套配置。
  • 图形化查看网络状态：
    OpenSurge 提供 Web GUI 和状态栏管理方式，可以查看连接状态、流量信息以及出口链路，降低手动维护 Mac 网关配置的复杂度。
  • 兼容已有 mihomo 配置：
    项目支持导入已有的 mihomo 配置，包括节点、代理组和分流规则，方便已经使用 Clash Meta / mihomo 生态的用户迁移现有规则。

这些能力让 OpenSurge 更偏向于局域网出口管理，而不是单纯的代理客户端。它需要依赖稳定运行的 Mac 设备和一定网络配置基础，实际使用效果也取决于当前网络环境。

OpenSurge for Mac 部署要求与使用限制

虽然 OpenSurge 提供了图形化界面，但它仍然涉及 DHCP、DNS 和网络转发配置，更适合有一定局域网基础的用户使用。在部署前，需要了解几个实际限制。

部署前需要注意：

  • 硬件常驻：
    如果将 Mac 作为局域网网关使用，需要保持设备开机并关闭自动休眠。比较适合长期运行的 Mac mini 或闲置 Mac 设备。如果网关设备关闭或休眠，下游设备可能无法继续通过该网关访问网络。
  • 网络配置要求：
    项目涉及 DHCP 接管、DNS 分发以及旁路由配置，用户需要了解基础局域网结构和主路由设置方式，否则可能出现 IP 冲突或网络配置异常。
  • 透明代理限制：
    当前透明代理方案依赖 mihomo 的 TUN 模式实现。部分旧版 pf TCP 重定向方案在当前 macOS 环境下并不适用，具体支持情况需要参考项目当前版本文档。

如果需要进一步配置 DHCP 接管、mihomo 规则或透明代理参数，建议根据项目 GitHub 文档进行设置，不同家庭网络结构可能需要调整具体配置。

OpenSurge for Mac 适合哪些用户？

OpenSurge for Mac 更适合需要管理多台网络设备，并且愿意了解局域网配置的用户。它更适合希望管理多台网络设备，并且愿意了解局域网配置的用户。

如果家里有 Apple TV、PS5、Switch 或智能电视等无法直接安装客户端的设备，同时手里有一台可以长期运行的 Mac，那么这种网关方案会比单独给每台设备配置网络更加灵活。

不过，这种方案也增加了维护成本。运行 OpenSurge 的 Mac 需要保持在线，用户也需要了解 DHCP、DNS、旁路由等基础网络概念。如果只是单台 Mac 电脑使用代理，普通桌面客户端通常更加简单。
