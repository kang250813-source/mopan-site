CodexBar：开源的 AI编程工具用量监控软件（支持 Cursor / Claude 等50+ 个 AI 服务）

Published 2026-06-17

编辑备注：本文基于 CodexBar 公开仓库与文档整理。由于该工具需要读取本地登录状态，部分服务的监控稳定性可能会随着官方客户端或网页端风控规则的更新而变动。

CodexBar 是一个能让你在 Mac 菜单栏里，一眼看清多个 AI 编程工具还剩多少调用配额的监控软件。

如果你平时重度依赖 AI 写代码，肯定遇到过这种尴尬情况：手感正热，连敲了一堆需求，Cursor 或 Claude 突然弹窗提示说高级模型额度用光了。现在的开发者往往会混用多个 AI 工具，各家的计费周期、重置时间和用量看板散落在不同的后台里，每次想看还得专门打开浏览器登进去查，查起来费时费力。

CodexBar 是一款基于 MIT 协议开源的轻量级工具。它能把 Cursor、Copilot、Claude Code、Gemini、OpenRouter、DeepSeek、Kimi、MiniMax 等50+ 个 AI 服务的剩余额度、费用信息和重置倒计时，整理到系统菜单栏里。它最大的优点是复用本机已有的登录状态，更适合懂代码、多工具混用的用户。

为什么需要单独的 AI 编程工具用量监控软件？

其实自己写个脚本去调 API 查余额并不难，但 CodexBar 真正聪明且省事的地方在于它的“本地状态复用”机制。

不少在线监控面板需要用户把 API Key 交给第三方服务处理，这对开发者来说会多一层数据流向顾虑。CodexBar 的思路不太一样，它更偏本地读取：复用 OAuth、设备授权 Token、CLI 本地配置文件、浏览器 Cookie 或 API Key，在本机整理出用量和额度信息。

这种方式的好处是省去了反复登录各家后台的麻烦；需要注意的是，不同服务的接入方式不一样，有些服务仍然需要手动填 API Key，有些则依赖浏览器 Cookie 或本地 CLI 配置。所以它不是“完全零配置”，更适合愿意花一点时间做初始设置的用户。

 

权限提醒：
CodexBar 省事的地方，是直接复用本机已有的登录状态；需要注意的地方，也正是这里。部分服务需要读取浏览器 Cookie、CLI 配置或 Keychain 凭证，macOS 可能会弹出完全磁盘访问权限、钥匙串访问等提示。介意这类权限的话，建议只开启自己确实需要监控的服务，并先看一下项目里的权限说明。

CodexBar 能看到哪些 AI 编程工具用量数据？

安装在菜单栏或者使用桌面小组件后，你能直观监控到几项关键指标：

  • 会话配额与重置倒计时：比如明确显示你的高级对话次数（Session / 周 / 月）分别还有多久刷新。
  • 账单与费用统计：对于支持 API、账单接口或本地用量扫描的服务，能查看费用、余额或用量趋势，具体展示深度取决于服务商开放的数据，能实时看清花了多少钱，避免跑超。
  • 状态监控与预警：它会轮询服务商的状态页，当 API 接口出现故障时，菜单图标上会出现提示标记。

 

CodexBar 怎么安装和使用？

CodexBar 的安装方式比较简单。macOS 用户可以从 GitHub Releases 下载应用，也可以用 Homebrew 安装：brew install --cask steipete/tap/codexbar。Linux 用户主要使用官方提供的 CLI 命令行版本。

首次打开后，在设置里选择自己正在使用的服务，比如 Claude Code、Cursor、Copilot、Codex、OpenRouter、DeepSeek 等。不同服务的接入方式不一样，有的走 OAuth，有的读取本地 CLI 配置，有的需要浏览器 Cookie 或 API Key。

配置完成后，它会把对应服务的额度、费用或重置时间显示在菜单栏里。建议一开始只开启自己常用的几个服务，确认权限提示和数据显示都正常后，再逐步添加更多平台。

CodexBar 适合哪些 AI 编程工具用户？

CodexBar 不是那种装了就人人都能受益的软件。

如果你只是偶尔用 AI 问个代码问题，或者只订阅一个工具，其实没必要专门装它。多一个菜单栏图标，还要处理权限弹窗，收益不一定明显。

它更适合重度 AI 编程工具用户。比如 Cursor、Claude Code、Copilot、Codex 混着用，或者还会接 OpenRouter、DeepSeek、AWS Bedrock 这类按量计费服务。对这类用户来说，提前知道额度还剩多少、什么时候重置、这个月花了多少钱，确实能少很多临时查后台的麻烦。

平台差异也别忽略，尤其是你不是 macOS 用户的话：

  • macOS：体验最完整，菜单栏图形界面主要面向 macOS 14 及以上版本。
  • Linux：官方主要提供 CLI 工具，桌面面板体验需要借助 Waybar、GNOME 扩展这类社区方案。
  • Windows：目前没有官方版本，GitHub 上有独立的 Win-CodexBar 项目，但属于社区实现，功能和更新节奏需要单独看。

如果你不需要这么多平台统一监控，只想盯住单个服务，也可以看看之前整理过的 DeepSeek API 用量监控工具 和 Agent Battery。前者更偏 DeepSeek API 余额与 Token 消耗，后者更适合 Claude Code 用户查看 Mac 状态栏用量。
