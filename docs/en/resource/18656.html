CopyTranslator：开源复制翻译工具，支持 PDF 断行优化与 AI 翻译

Published 2026-06-26

读外文 PDF 和长篇文献时，复制出来的内容经常被硬换行切碎。CopyTranslator 把“复制、去换行重组、调用翻译引擎”这几步串在一起，复制文本后自动清理断句并显示译文，还能接入 DeepSeek 这类云端 API，或调用本地 Ollama 模型。

CopyTranslator 解决的就是这个问题。它是一款开源复制翻译工具，会监听剪贴板内容，在你复制文本后自动处理多余换行和断句，再把整理后的内容交给翻译引擎。它更适合在 PDF 阅读器、Word、IDE 等本地应用里使用，而不是只服务于浏览器网页。

怎么选：网页阅读优先用沉浸式翻译插件；PDF、论文、本地文档和跨应用复制翻译，更适合用 CopyTranslator。如果还想接入 DeepSeek、Ollama 这类 AI 模型，它的自由度会更高。

CopyTranslator 是什么：一款适合 PDF 阅读的开源复制翻译工具

浏览器里的划词翻译插件，在网页上通常很顺手；但一到 macOS 预览、Adobe Reader、SumatraPDF 这类原生 PDF 阅读器，体验就不一定稳定。CopyTranslator 的优势正好在这里：它不依赖网页环境，而是通过剪贴板接收你复制出来的文本。

用它读 PDF 时，流程很接近“复制原文，旁边直接看译文”。CopyTranslator 会监听剪贴板内容，先把 PDF 里常见的硬换行、多余断句整理成连续段落，再交给翻译引擎处理。译文可以显示在悬浮窗口里，也可以配合专注模式、对照模式放在屏幕边缘查看。

如果一段内容被 PDF 分页或排版切开，也可以配合增量复制继续拼接处理，比较适合长论文、技术手册和跨页段落。

这样读论文、技术文档或本地资料时，就不用反复在 PDF 阅读器和翻译网页之间切换，也不用手动删换行。CopyTranslator 真正省下来的，是外文阅读里最烦的复制清洗步骤。

支持 AI 大模型接口：可接入 DeepSeek、Ollama 等翻译引擎

不少复制翻译工具会绑定固定翻译源，用起来省事，但模型选择空间有限。CopyTranslator 在 v12 版本后加入了大模型 AI 翻译能力，支持接入符合 OpenAI 格式 API 的服务，并提供 OpenAI、DeepSeek、Moonshot、智谱、Ollama、Azure OpenAI 等预设模板。

这意味着你可以把 CopyTranslator 当作一个本地翻译入口：云端可以接 DeepSeek、Moonshot、智谱这类 API，本地可以接 Ollama。最终翻译质量主要取决于你启用的模型和提示词配置，CopyTranslator 负责把复制、文本清理和翻译调用串起来。

接 AI 模型前要注意：CopyTranslator 本身是免费的开源软件，但接入 DeepSeek、Moonshot、智谱这类云端大模型后，复制的文本会发送到对应服务商处理，费用也按对方的 Token 规则计算。要是翻译内部资料、合同、客户信息这类敏感内容，本地 Ollama 会更可控一些，但仍要看模型来源、网络环境和软件设置，不能简单理解为“用了本地模型就绝对安全”。

和沉浸式翻译相比，CopyTranslator 更适合本地文档阅读

如果你主要看的是网页，沉浸式翻译这类浏览器插件会更省事。打开网页就能看到双语对照，不需要复制，也不需要额外开一个窗口。

但 CopyTranslator 的优势不在网页，而在“浏览器之外”。比如 PDF 阅读器、本地 Word 文档、代码 IDE、桌面客户端里的英文内容，只要能复制出来，它就可以通过剪贴板接住，再把文本整理后交给翻译引擎处理。

这也是它适合论文、技术文档和本地资料阅读的原因。很多 PDF 复制出来会带硬换行，普通翻译工具容易把一句话拆散；CopyTranslator 更像是在复制和翻译之间加了一层文本清洗，把这一步提前处理掉。

如果你还想用 DeepSeek、Moonshot、智谱这类云端大模型，或者接本地 Ollama 做翻译，CopyTranslator 的可玩性会更高。它不把你锁死在某一个翻译平台里，翻译效果主要取决于你接入的模型。

更准确地说，CopyTranslator 不是用来替代所有翻译工具的。网页阅读可以继续用沉浸式翻译，零散查词可以用浏览器自带功能；它更适合那些经常读 PDF、论文、本地文档，并且愿意花一点时间配置翻译源的人。
