holaOS AI Agent 工作区：让 Claude Code 与 Codex 共享记忆和工具

发布于 2026-08-16

holaOS 是一个面向长期 AI 任务的开源桌面工作区（Agent Workspace）。它不是另一个单纯的 AI 对话客户端，而是把项目记忆、本地文件、MCP 工具和自动化任务放进统一的 Workspace，让 Claude Code、Codex 等不同 Agent 共用同一个运行环境。

对同时使用多个 Agent 的开发者来说，这解决的是一个很实际的问题：换工具之后，不需要从头重新准备项目背景、工具连接和工作区配置。holaOS 还支持 BYOK 与 Ollama，本地文件和长期记忆也可以跟着 Workspace 保留下来。

大白话解说：普通 AI 对话更像临时工，每次换人都要重新交代背景；holaOS 则把项目资料、记忆和工具留在固定 Workspace 里，Claude Code 或 Codex 接进来后直接使用这套环境。

holaOS 和直接使用 Claude Code、Codex 有什么区别？

Claude Code、Codex 等 Agent 本身都能保留一定的项目配置和上下文，但这些状态通常留在各自的工具和运行环境里。换到另一个 Agent 后，之前配置好的记忆、工具连接和工作规则不会自动跟过去。

holaOS 不把项目状态绑在某一个 Agent 上。 Claude Code、Codex 可以换着用，项目记忆、本地文件和已经接入的工具则继续留在同一个 Workspace 里。简单理解，就是 Agent 可以换，Workspace 尽量不换。

  • Workspace 留住项目上下文： Claude Code、Codex 等 Agent 可以在同一个工作区里处理任务，项目记忆、本地文件和相关规则围绕 Workspace 组织，不必完全依赖某一个 Agent 的会话历史。
  • 减少重复配置： 已连接的工具、MCP 能力和工作区设置可以被不同 Agent 复用，切换 Agent 时不用重新准备一套完全独立的工具环境。
  • 记忆可以直接查看： Workspace 的记忆以本地文件形式保存，用户可以自己打开、修改和整理，也方便后续做版本管理。

holaOS AI Agent 工作区的记忆、工具与应用

除了共享底层记忆，holaOS 在交互方式和任务产出上也做了一些针对桌面端场景的优化：

  • HolaApps 与人工干预： holaOS 的 HolaApps 可以把 Notion、浏览器等应用以真实可交互界面的形式放在 Agent 旁边。Agent 执行网页或应用操作时，用户可以直接看到当前界面和操作过程，发现偏差时也能介入处理，而不是只能等待后台任务结束后再检查结果。
  • 原生办公文件产出： 不仅限于在聊天窗口输出代码或 Markdown 文本，还可以直接生成 .xlsx、.docx、.pptx 等文件。
  • 多渠道任务触达与自动化： 支持定时任务与事件触发机制，执行完成后可通过 Slack、Telegram、飞书等渠道返回摘要或文件。

holaOS 支持哪些 Apps？还能通过 MCP 扩展吗？

holaOS 可以连接 Gmail、GitHub、Notion、Slack 等常用服务，接入后可以让不同 Agent 继续使用这些工具。除了官方提供的 Apps，也支持通过 MCP Server 接入自己的工具和服务。

holaOS 的 Apps 还在持续增加，官方资料里的集成数量也会随版本变化，所以这里不把具体数量当成固定指标。如果现成 Apps 里没有需要的服务，还可以通过 MCP 继续扩展。

对已经在 Claude Code、Codex 中使用 MCP 的用户来说，原有工具链也有机会继续接进 holaOS，不必完全依赖官方预置应用。

内置模型、BYOK 与 Ollama 的使用成本怎么选？

用 holaOS 跑长任务时，持续注入记忆和多轮调用工具通常也意味着更多模型请求和 Token 消耗。模型方面，目前可以直接用内置服务、接自己的 API Key，也可以连接 Ollama。

  • 内置模型： 不需要自行配置 API Key，可以直接使用 holaOS 提供的模型服务。实际可用模型、免费额度和套餐规则以当前官方方案为准。
  • 自带密钥（BYOK）： 可以接入自己的 OpenAI、Anthropic 或 OpenRouter API Key，调用按所接入服务商的账户和费率计费。已经有 API 账号、希望自己决定模型和控制费用的用户，更适合这种方式。
  • 本地模型（Ollama）： 可以连接本机或局域网中的 Ollama。使用本地模型不会产生对应的外部模型 API 账单，但会占用自己的内存、算力和电力，实际速度与效果也取决于硬件和所选模型。

如果任务需要持续读取长期记忆、反复调用 MCP 工具或执行较长的 Agent 循环，使用商业模型时的 Token 消耗也可能比普通聊天场景更高。BYOK 并不一定更便宜，它的优势主要是模型、账户和计费方式由自己决定。

本地运行，不代表所有数据都留在本机：Workspace 和 Ollama 可以运行在自己的设备上，但只要接入 OpenAI、Anthropic 等外部模型 API，或者连接 Gmail、Notion 等第三方云服务，相关数据仍可能按照任务需要发送给对应服务商。

holaOS 支持哪些系统？怎么安装？

holaOS 基于 Electron 和 TypeScript 开发，源码支持 macOS、Windows 和 Linux。目前官方现成安装包仍以 macOS 为主，同时提供 Apple Silicon 和 Intel 版本。

Windows 和 Linux 也能运行 holaOS，但现阶段更可能需要按照项目文档从源码安装。项目发行状态变化比较快，如果你不是 macOS 用户，安装前直接查看 GitHub Releases，会比参考较早的安装教程更准确。

holaOS 开源吗？Modified Apache 2.0 有哪些限制？

holaOS 的源码公开，但许可证不是标准 Apache 2.0，而是 Modified Apache 2.0。

按照当前 LICENSE，个人使用和单个组织内部使用不需要额外商业许可证，包括同一组织内使用多个 Workspace。限制主要出现在对外商业化：如果把 holaOS 做成面向第三方提供的托管 SaaS，或者作为组件嵌入商业产品销售、授权或分发，需要取得项目方的商业授权。

前端还有单独的品牌要求。使用 holaOS 前端时，项目中的 Logo 和版权信息不能随意删除或修改。

所以，如果只是个人使用、企业内部部署或研究源码，这套许可通常不会成为主要障碍；如果准备基于 holaOS 做 SaaS、商业分发或二次产品，最好直接查看仓库里的最新 LICENSE，再确认具体授权范围。

holaOS 的企业与团队使用：权限、审计与部署

holaOS 不只面向个人开发者，官方也提供团队和企业使用方式。相比个人桌面端，企业场景更关注的不是能接多少个模型，而是 Agent 能访问哪些内部系统、谁有权限调用工具，以及执行过程能不能留下审计记录。

  • SSO 与权限控制： 企业方案支持围绕 Agent、Skills 和 Apps 做身份与权限管理，减少所有成员共用同一套高权限连接的风险。
  • 操作审计： 对 Agent 执行过的操作保留审计记录，更适合需要追踪自动化行为和内部合规检查的团队。
  • 内部系统接入： 可以将 Agent 与企业内部工具和数据源连接，但实际的数据访问范围仍取决于团队配置的权限、MCP 服务和第三方集成。
  • 部署方式： 官方提供面向企业环境的部署选项，包括企业自有基础设施等场景。具体的部署能力、授权范围与商业价格应以官方企业方案为准。

如果只是个人开发者使用，这些企业功能通常不是选型重点；但对于准备把 Agent 接入代码仓库、内部文档、CRM 或其他业务系统的团队，权限隔离、审计日志和部署方式的重要性会明显高于单纯比较模型能力。

holaOS 更适合哪些用户？

更适合以下人群：

  • 日常频繁使用 Claude Code、Codex 等工具，希望统一管理本地环境与持久记忆的开发者；
  • 需要让 Agent 操作浏览器或第三方应用，且要求执行过程可视、随时能够介入接管的用户；
  • 对数据资产可读性有要求，希望工作区配置文件和记忆以本地明文形式保存的折腾党。

可以先观望的人群：

  • 对只需要基础问答、文档翻译和简单润色的轻度用户，常规单一网页端已足够满足需求，该工作区的配置和调度成本可能超出实际价值；
  • 非 macOS 平台且不具备基础 Node.js 源码构建经验的普通用户。
一句话结论：如果你经常在 Claude Code、Codex 之间切换，holaOS 最有价值的地方就是把记忆、文件和工具留在 Workspace 里，不必每换一个 Agent 就重新搭一遍环境。
