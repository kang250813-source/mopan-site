Scrubshot：开源截图自动打码工具，本地识别手机号、身份证和 API Key

发布于 2026-11-26

写教程、提工单或者发聊天记录时，截图里难免会带上一些不该公开的信息：一个手机号、一串 Token、一行内网 IP。手动一个个找容易漏，有些在线打码工具还需要先把原图上传到服务器。

Scrubshot 是一款开源的截图自动打码工具。把截图粘贴到网页中，它会在浏览器本地通过 OCR 识别手机号、身份证、银行卡、API Key 等敏感信息，自动标记或遮盖对应区域。

和普通的图片马赛克工具不同，Scrubshot 默认使用不透明的黑色色块覆盖敏感文字，支持批量处理，也可以部署在自己的电脑或服务器上。

Scrubshot 能自动识别哪些敏感信息？

Scrubshot 默认使用 RapidOCR（PP-OCRv5）识别截图中的文字，并以 Tesseract 作为备用识别引擎，再通过 14 条正则规则、校验位算法和上下文判断，找出可能涉及隐私或安全风险的内容。

信息类型 支持识别的内容
个人信息 手机号、身份证、邮箱、地址、座机号码
金融信息 银行卡号码
开发者凭据 API Key、JWT、私钥
网络信息 内网 IP、包含 Token 的 URL
业务信息 部分长订单编号

比较实用的是，Scrubshot 不会把所有识别结果一律涂黑，而是根据风险和检测结果分级处理：

  • 红色：高风险信息，自动添加遮挡。
  • 黄色：中风险信息，标记出来等待核对。
  • 白色：低风险信息，仅提供提示。

即使疑似银行卡或身份证号码没有通过校验位检查，也不会被直接丢弃，而是降级为疑似信息。对于脱敏工具来说，多提醒一次通常比漏掉一串敏感号码更容易接受。

Scrubshot 还支持部分长号码的跨行拼接识别，以及低置信度截图的水平镜像识别。比如聊天记录中的身份证号码被折成两行时，跨行拼接可以减少只遮住一半的情况。

如何使用 Scrubshot 给截图自动打码？

打开 Scrubshot 网页，直接粘贴剪贴板中的截图，也可以把图片拖进去。识别完成后，右侧会列出检测到的敏感信息及原文片段，确认哪些需要遮挡，补上遗漏的地方，就可以导出图片了。

如果平时需要处理大量订单截图、聊天记录或者后台操作截图，也不用一张张上传和下载。Scrubshot 支持批量导入图片，每张图的编辑和撤销记录相互独立，处理完可以直接打包成 ZIP 下载。

不过，Scrubshot 主要针对截图里的文字信息。如果想自动遮挡照片或视频中的人脸、车牌，可以试试之前介绍过的武松打码。

为什么截图打码不建议只用马赛克或模糊？

高斯模糊和马赛克虽然能降低文字的可读性，但在特定条件下，仍可能保留足够的信息供识别或推断。如果遮挡的是密码、身份证号码或者 API Key，更适合使用完全不透明的色块。

Scrubshot 默认使用黑色色块，也提供模糊和像素化选项，选择模糊处理时会弹出风险提示。

查看项目的图片导出源码可以发现，它会通过 Canvas 按原图尺寸重新绘制图片，将遮挡效果直接写入导出的位图，而不是仅在原图上添加一个可移除的遮挡图层，支持 PNG、JPEG 和 WebP 格式。

重新编码后的图片也不会直接携带原始文件的 EXIF、GPS 信息及 EXIF 缩略图，不过原始 ICC 色彩配置同样不会保留。

当然，黑框只有完整覆盖敏感区域才有效。如果边缘还露出几个字符，或者某段文字根本没有被识别出来，仍然存在泄露风险。

如果需要处理的不是截图，而是合同、账单等 PDF 文件，可以参考AnyRedact PDF 自动脱敏工具。PDF 脱敏还需要考虑原始文字层是否被真正移除，不能只在页面上覆盖一个黑框。

Scrubshot 会上传图片吗？有哪些限制？

Scrubshot 比较吸引人的地方，是它不需要把截图上传到服务器再进行识别。项目从 OCR 文字识别、敏感信息检测到图片导出，整个过程都在浏览器本地完成。

不过，第一次使用可能会慢一些，需要加载约 58MB 的 OCR 模型和运行资源（gzip 压缩后约 21MB，实际大小随版本而异），加载完成后，即使断开网络也能继续处理截图。

这里有个细节需要注意，作者提供的在线演示使用的是 IP 地址加 HTTP 端口，并没有 HTTPS 加密。体验功能没什么问题，但如果要处理真实的身份证、客户资料或者服务器密钥，还是建议自己在本地运行一份。

自动打码的识别效果怎么样？

作者公开了一组测试数据，在 30 张合成截图的 157 个敏感信息标注项中，RapidOCR 成功识别了 155 项，文本检测召回率为 98.7%。这个成绩仅代表作者的测试集，并不意味着所有截图都能达到同样的效果。

比如一些没有明显特征的订单编号、病历号，就可能被漏掉；横着拍或者倒过来的图片，目前也不支持自动旋转纠正。如果同一行有多个敏感词，还可能被合并到一个遮挡框里。

另外，识别到敏感文字和完整遮住文字是两回事。像二维码、签名、人脸，以及只有自己才知道需要保密的内部信息，还是得手动检查一下。

所以，即使使用了自动打码工具，图片发出去之前也值得再看一眼。如果 API Key 或 Token 已经泄露，记得及时撤销或更换，而不是仅仅把原来的截图重新打码。

如果需要脱敏的不是截图，而是准备发给 ChatGPT、Claude 的日志、配置文件或其他文本内容，还可以看看之前介绍的Privacy Filter 本地隐私脱敏工具。

Scrubshot 本地运行与自托管部署

如果不想使用作者提供的在线演示，也可以自己部署一份 Scrubshot。项目采用 MIT 开源许可证，整个应用构建后就是一套静态网页，不需要搭建后端服务，也不用额外维护数据库。

想在自己的电脑上运行，按照项目要求准备好 Node.js 和 pnpm（项目文档要求 Node.js 20+、pnpm 11+，同时需要满足 pnpm 的运行环境要求），拉取源码即可：

git clone https://github.com/strugglesky/scrubshot.git
cd scrubshot
pnpm install
pnpm dev

启动后访问 http://localhost:5173，就可以在本地使用。

如果手里有闲置的 VPS 或 NAS，也可以通过下面的命令生成静态网页文件：

pnpm build

将生成的 dist/ 目录部署到 Nginx、Vercel 或 Netlify 上即可。对于使用宝塔面板的用户，创建一个静态网站、上传构建好的文件，再配置 HTTPS 就行，不需要单独运行 Node.js 服务。

不过，如果打算部署到 Cloudflare Pages，需要留意一下文件大小。项目目前使用的 ONNX Runtime 中，部分 WASM 文件约为 28MB，超过了 Cloudflare Pages 单文件 25MiB 的限制，直接部署可能会失败。

这也是 Scrubshot 比较适合自托管的地方：OCR 识别主要消耗的是用户设备的计算资源，而不是服务器算力，服务器主要负责提供网页和模型文件，没有必要专门为它准备一台高配置机器。

更多安装细节及常见构建问题，可以参考项目开发文档。
