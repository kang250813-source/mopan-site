Netlib 自动登录保活脚本是什么？

Netlib 自动登录保活脚本是一个开源工具，用于自动登录 Netlib 网站（netlib.re），帮助用户保持账号与免费二级域名处于活跃状态。脚本通过 GitHub Actions 定时执行，无需本地部署服务器，只要完成一次配置，就能每 60 天自动运行一次，为 Netlib 账户执行登录保活操作。

  • 官网 / 注册地址：https://www.netlib.re
  • 视频教程：https://youtu.be/7laVmEfgC9o
  • 项目地址：https://github.com/eooce/Auto-login-netlib

Netlib 提供免费二级域名，DNS 已经支持托管到 Cloudflare，对想要低成本尝试个人站点、工具服务或内网穿透域名的用户很友好。

功能亮点

核心特性

  • 🔐 自动登录 Netlib 账号
    支持单账号与多账号登录，适合有多个 Netlib 账号或多个免费二级域名的用户。
  • 👥 多账户批量处理
    通过一个环境变量即可配置多组账号密码，统一由 GitHub Actions 批量执行登录任务。
  • ⏰ 每 60 天自动执行一次
    脚本默认每 60 天运行一次，覆盖 Netlib 一般的活跃检测周期，降低域名被回收或账号失效风险。
  • 📱 Telegram 通知支持
    可选配置 Telegram 机器人与聊天 ID，在每次执行任务后通过 Telegram 收到运行结果提醒，便于远程查看脚本状态。
  • 🌐 支持免费二级域名保活 + Cloudflare DNS
    Netlib 提供免费二级域名，结合 Cloudflare DNS 托管，可以更轻松地搭建个人服务、测试环境或自建工具。

使用场景

谁适合使用这个脚本？

  • 使用 netlib.re 免费二级域名，希望域名长期处于可用状态的个人或开发者
  • 不想经常手动登录 Netlib 检查状态，只希望自动完成「保活」的站长
  • 维护多个 Netlib 账户，希望用一个脚本统一管理登录任务的进阶用户
  • 喜欢用 GitHub Actions 处理日常运维小任务的技术爱好者

快速开始：如何使用 Netlib 自动登录保活脚本？

Step 1：Fork 项目

在 GitHub 上访问项目地址：
https://github.com/eooce/Auto-login-netlib

点击右上角 Fork，将仓库复制到自己的 GitHub 账号下，方便后续配置 Actions 与 Secrets。

Step 2：启用 GitHub Actions

进入 Fork 后的仓库：

  1. 打开 Actions 菜单
  2. 点击提示中的 “I understand my workflows, go ahead and enable them” 按钮
  3. 让仓库的工作流处于启用状态，脚本才能定时运行

Step 3：配置环境变量（Secrets）

在仓库中打开：
Settings → Secrets and variables → Actions，添加以下环境变量：

1. 必填：ACCOUNTS

  • 变量名：ACCOUNTS
  • 用于存放 Netlib 账号信息
  • 账号密码之间用英文冒号 : 分隔，多账号之间用英文逗号 , 分隔

格式示例：

  • 单账号：
    • user:pass
  • 多账号：
    • user1:pass1,user2:pass2,user3:pass3

2. 可选：Telegram 通知相关变量

如果需要在任务执行完成后，通过 Telegram 接收通知，可以继续配置以下环境变量：

  • BOT_TOKEN：Telegram 机器人 Token
    • 在 https://t.me/BotFather 创建机器人后获取
  • CHAT_ID：Telegram 聊天 ID
    • 可通过 https://t.me/laowang_serv00_bot 发送 /start 获取聊天 ID

如果不需要消息通知，可以不配置 BOT_TOKEN 与 CHAT_ID 两个变量，脚本依旧可以正常执行保活任务。

Step 4：手动执行一次检查配置

在 GitHub 仓库的 Actions 页面中：

  • 选择对应的工作流
  • 手动触发一次运行
  • 确认账号配置正确、Secrets 无误

脚本运行成功后，后续会按照预设计划，每 60 天自动执行一次。

注意事项

  • 确保 Netlib 账户密码填写准确，否则自动登录会失败
  • GitHub Actions 第一次运行可能需要你在界面中授权
  • 脚本默认执行时间为 UTC 0:00，对应香港时间约为 08:00，属于常规工作时间段
  • 不配置 Telegram 环境变量时，只是不会推送通知，不会影响登录与保活功能
  • 建议定期查看 GitHub Actions 运行日志，了解脚本状态与 Netlib 账号是否正常登录
