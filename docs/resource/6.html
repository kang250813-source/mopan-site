Google Flights MCP：Fli 让 Claude、CLI 和 Python 都能查航班

发布于 2026-10-31

如果想让 Claude 直接查询 Google Flights，可以用开源项目 Fli 给它接入 Google Flights MCP。配置完成后，可以直接让 Claude 查询指定日期的航班、比较不同机场和舱位，也能在一段日期范围内找价格较低的出发日。

Fli 不只提供 MCP Server，还可以通过 CLI 和 Python 使用，比较适合已经在用 Claude Desktop、MCP 客户端，或者想把航班查询接进脚本的用户。项目采用 MIT License，源码和安装说明都可以在 Fli 的 GitHub 仓库 查看。

需要注意的是，Fli 在 2026 年已经调整过 Google Flights 数据的获取方式。当前版本仍然可以完成单程、往返和低价日期查询，但多城市搜索、Booking Options，以及部分筛选条件已经受到限制。下面会从实际使用出发，把安装方法、Claude 接入方式、能查什么，以及目前不能做什么讲清楚。

说明：本文依据 Fli 当前 GitHub README 与 Google 官方文档整理。Fli 依赖 Google Flights 当前的搜索页面和数据结构，后续版本的功能与限制可能继续变化。

Google Flights MCP 能查什么？

接入 Fli 之后，可以直接让 Claude 查询指定日期的航班，也可以给它一段时间范围，让它帮你找价格相对低的出发日。

比如可以直接问：

  • 12 月 20 日从旧金山飞东京有哪些商务舱直飞？
  • 下个月纽约飞伦敦，哪几天价格比较低？
  • 只看 Oneworld 航空联盟，并排除某家航空公司。
  • 从 JFK、EWR、LGA 三个机场一起找价格更合适的航班。

航班查询主要会用到 Fli 的两个核心工具：

工具 适合做什么
search_flights 查询指定日期的单程或往返航班，并按舱位、航司、中转次数、出发时间等条件筛选
search_dates 比较一段日期范围内的航班价格，用来寻找相对便宜的出行日期

除了 Claude 这类 MCP 客户端，Fli 也可以直接在命令行或 Python 代码里使用。所以它比较适合两类场景：一种是让 AI 助手帮忙查航班，另一种是把航班查询接进自己的脚本、价格分析或自动化流程。

不过 Fli 目前主要解决的是航班搜索和初步比价，不是完整的订票服务。多城市搜索、Booking Options 和部分筛选条件目前也存在限制，后面会单独说明。

Google Flights MCP 可以怎么筛航班？

Fli 比较实用的地方，是可以把 Google Flights 里原本需要手动点选的很多条件一起交给 Claude 或脚本处理。

比如从纽约出发，不一定只查 JFK，也可以把 JFK、EWR、LGA 几个机场放在一起比较；跨洲航线则可以指定商务舱、只看直飞，或者限定 Oneworld、SkyTeam、Star Alliance 这类航空联盟。

目前常用的筛选条件包括：

  • 出发地、目的地以及多个机场组合
  • 经济舱、高级经济舱、商务舱和头等舱
  • 直飞、一次中转或更多中转
  • 指定或排除航空公司、航空联盟
  • 最短和最长中转时间、出发时间范围
  • 成人、儿童、占座婴儿和怀抱婴儿人数
  • 币种、语言和国家
  • 按价格、飞行时长、出发时间或到达时间排序

这些条件单独看并不特别，但组合起来就比较省事了。比如可以让 Claude “找下个月 JFK、EWR、LGA 飞伦敦的商务舱，最多一次中转，排除某家航司，并优先看价格低的日期”，不用自己在 Google Flights 里来回修改条件。

search_dates 则更适合日期比较。如果出发时间比较灵活，可以给它一个几周的范围，让它逐日查询价格，而不是先自己猜哪一天便宜。

往返搜索还有一个细节值得注意。Fli 会根据 top_n 继续展开去程对应的返程组合，所以一次查询可能产生 1 + top_n 次页面请求。top_n 默认是 5，最大 10。

默认值通常够用，但如果最前面的几个去程结果过于集中，比如几乎都是同一家航空公司，可以适当提高 top_n，或者更换排序方式再查。代价是请求次数也会跟着增加。

如何安装 Fli Google Flights MCP

项目推荐使用 pipx 安装 CLI 和 MCP Server：

pipx install flights

安装完成后可以先确认命令是否正常：

fli --help
which fli-mcp

STDIO 模式的 MCP Server：

fli-mcp

如果需要 Streamable HTTP 模式：

fli-mcp-http

默认 MCP 地址为：

http://127.0.0.1:8000/mcp/

如果只是本机 Claude Desktop 使用，一般直接配置 fli-mcp 就够了，不需要额外启动 HTTP 服务。

如果运行 fli-mcp 时出现 MCP dependencies are not installed，说明当前 Python 环境里缺少 MCP 的可选依赖。Fli 会提示安装带有 mcp extras 的版本，例如：

pip install 'flights[mcp]'

遇到这类报错时按终端提示补齐依赖即可，不影响 Fli 本身的 CLI 航班查询功能。

如何把 Fli 接入 Claude Desktop

macOS 下 Claude Desktop 的 MCP 配置文件通常位于：

~/Library/Application Support/Claude/claude_desktop_config.json

可以加入：

{
  "mcpServers": {
    "fli": {
      "command": "fli-mcp",
      "args": []
    }
  }
}

如果 Claude 找不到 fli-mcp，先运行：

which fli-mcp

然后把输出的完整路径写进 command，例如：

{
  "mcpServers": {
    "fli": {
      "command": "/Users/你的用户名/.local/bin/fli-mcp"
    }
  }
}

保存配置并重新启动 Claude Desktop 后，就可以直接用自然语言让 Claude 查询航班。

例如：

  • 帮我查 12 月 20 日从旧金山飞东京的商务舱，只看直飞。
  • 找一下下个月纽约飞伦敦相对便宜的出发日期。
  • 查询 JFK 到 LHR 的往返航班，优先按价格排序。
  • 只看 Oneworld，并排除指定航空公司。

Claude 会把这些自然语言条件转换成 Fli MCP 的参数，再调用 search_flights 或 search_dates。

CLI 和 Python 也可以直接使用

如果不需要 AI 助手，Fli 的 CLI 本身也能直接查询。

例如：

fli flights JFK LHR 2026-12-20 --class BUSINESS --stops NON_STOP --sort DURATION

查询一段日期范围：

fli dates JFK LHR --from 2026-12-01 --to 2027-01-10 --monday --friday

CLI 还支持 --format json 输出机器可读结果，不过项目目前仍把 JSON 格式标记为实验性能力，长期写进自动化脚本前最好考虑字段变化。

Python 版本可以直接安装：

pip install flights

TypeScript / JavaScript 用户则可以使用：

npm install fli-js

或者：

bun add fli-js

这些入口使用的仍然是 Fli 当前的航班搜索机制，因此后面提到的 Multi-city、Booking Options 等限制同样需要注意。

Fli 在 2026 年调整了航班数据的获取方式

Fli 现在获取 Google Flights 航班数据的方式，已经和早期版本不太一样。

从 2026 年 8 月开始，Google 调整了部分航班搜索请求的校验机制。Fli 原来使用的一些后端请求，即使能够正常返回，也已经拿不到完整的航班结果。

因此当前版本改为访问 Google Flights 的公开搜索页面，再从页面返回的数据中提取航班信息。

这个变化不会影响基本的安装和使用方式，但会影响部分功能。比如多城市搜索、Booking Options 和少数筛选条件目前已经无法正常使用，一次查询能够获得的航班结果数量也比以前少。

所以现在使用 Fli，比较需要关注的是它当前还能查什么、哪些功能已经受限。下面这些就是目前比较明显的限制。

Fli 查 Google Flights 有哪些限制？

Fli 目前已经能覆盖单程、往返、低价日期和不少常用筛选条件，但它还不能完全替代 Google Flights 网页，更不是一套完整的订票接口。实际使用时，下面几个限制比较容易遇到。

多城市行程暂时要分开查

如果行程是“纽约 → 伦敦 → 巴黎 → 纽约”这种多城市路线，目前不能一次交给 Fli 完成。比较实际的办法是把每一段拆开查询，再自己组合行程。

这里有个容易让人困惑的地方：Fli 的 CLI 目前仍然保留 fli multi 命令和多城市示例，但按照项目当前 Search Transport 的说明，底层多城市结果仍然不可用。所以看到 CLI 里还有这个命令，并不代表现在已经恢复了完整的 Multi-city 查询。

可以查航班，但不能直接完成订票

Fli 现在主要负责搜索和比价，Booking Options 暂时不可用。不过查询结果仍然可以生成对应的 Google Flights 链接，需要订票时再跳过去查看航空公司或代理商提供的价格和渠道。

行李、碳排放等筛选目前用不了

Google Flights 本身有很多细分条件，但 Fli 当前并没有全部保留下来。其中行李（bags）、碳排放（emissions）以及排除基础经济舱（exclude_basic_economy）目前不支持。

如果主要关心航司、舱位、中转次数、中转时间和出发时间，这些常用条件仍然可以正常使用。

条件设得太细，可能会出现空结果

Fli 一次拿到的候选行程数量有限，当前通常大约是 20～45 条。部分条件还是先取得航班结果，再在本地继续筛选。

这意味着如果同时指定航空公司、价格上限、出发时间、中转时长等很多条件，最后可能只剩几条，甚至一条都没有。遇到这种情况，可以先放宽一两个条件再查，不能直接理解成这条航线没有航班。

带儿童或婴儿时，结果可能更少

多人出行尤其是带儿童、婴儿时，Google Flights 返回给 Fli 的可用结果可能比单独查询成人少。

如果一加入儿童或婴儿就没有结果，可以先用成人条件确认航班，再回到 Google Flights 查看对应班次的实际家庭票价。

找低价日期适合查一段时间，但别把范围拉得太大

search_dates 会逐日查询指定范围内的价格，目前一次最多覆盖约 93 个日期。

拿它比较未来几周或者两三个月的出发日期很合适，但如果想长期、大范围持续扫描价格，请求量会明显增加。

高频查询的稳定性不能和商业 API 相比

Fli 的数据最终还是来自 Google Flights，所以连续大量查询时，可能遇到限流、空结果或者临时请求失败。云服务器、VPN 等网络环境下也可能出现不同情况。

日常给 Claude 查几趟航班问题不大；如果准备做长期价格监控、大批量查询或商业服务，就不能把它当成有稳定 SLA 的航班数据 API。

Fli 是 Google 官方的 Google Flights MCP 吗？

不是。

Fli 是社区维护的开源项目，并不是 Google 官方推出的 Google Flights MCP Server。

这里容易和另外两个 Google 产品混淆。

Google Flights Search 不是普通开发者公共 API

Google 官方确实有 Google Flights Search，主要用于向用户展示航班以及航空公司、OTA 等合作伙伴的预订链接。

不过这套体系并不是普通开发者注册后就能直接申请 API Key 使用的通用 Google Flights Public API。所以网上提到的“Google Flights API”，很多时候实际指的是第三方航班 API、社区项目，或者对 Google Flights 数据的非官方访问方案。

Google 官方还有一个 Travel Impact Model MCP

Google 还提供官方的 Travel Impact Model MCP，但它的用途主要是计算航班碳排放，并不是用来搜索机票价格或比较航班的。

简单来说，Fli 解决的是航班搜索和比价，而 Google Travel Impact Model MCP 解决的是航班排放数据，两者虽然都和航班、MCP 有关，但用途并不一样。

Fli 和商业航班 API 的区别

对比 Fli 商业航班 API
主要用途 航班搜索、MCP、脚本 航班数据、库存、订单等
成本 项目本身开源 通常按请求或套餐收费
Claude MCP 直接提供 MCP Server 一般需要自行封装
稳定性 受 Google 页面变化影响 通常有正式 API 契约
SLA 没有 部分供应商提供

所以如果只是给 Claude、Cursor 或自己的 Agent 增加航班查询能力，Fli 的接入门槛很低。

但如果你准备做正式的机票预订平台、企业差旅系统、大规模价格监控或者需要稳定 SLA，就不应该把这类社区项目直接当成商业航班 API 的替代品。

什么情况下值得用 Fli？

如果你平时已经在用 Claude Desktop、Cursor 这类 MCP 客户端，Fli 最直接的价值就是省掉反复打开 Google Flights 改条件的步骤。像多机场一起比、换几组日期、限制舱位和中转次数，这些都可以直接交给 Claude 去查。

对开发者来说，它也不一定非要配合 AI 使用。CLI 和 Python 接口更适合做一些重复查询，比如定期看某条航线价格、比较一段时间里的低价日期，或者把航班数据接进自己的脚本。

但如果只是偶尔查一次机票，其实没必要专门装 Fli，直接打开 Google Flights 会更快。它更适合那些查询条件比较多、经常需要反复比较，或者本身就已经在用 MCP 工作流的人。

另外，Fli 目前并不适合拿来做完整的订票系统。多城市、Booking Options 和高频稳定调用都有明显限制，如果是正式的企业差旅、机票预订或大规模价格监控，还是要考虑提供正式接口和稳定服务的航班 API。

如果你对这类交通查询 MCP 感兴趣，也可以看看站内的 12306 MCP Server，一个查铁路，一个查航班，使用思路比较接近。

如果你的需求就是让 Claude 帮忙查航班，或者经常需要在多日期、多机场和不同筛选条件之间反复比较，Fli 确实有实用价值；偶尔查一次机票，直接用 Google Flights 更省事。至于正式订票、大批量查询或企业级应用，就更适合考虑有稳定接口和服务保障的航班 API。

常见问题

Google Flights MCP 需要 API Key 吗？

Fli 本身不要求申请 Google Flights API Key。安装完成后即可运行 MCP Server。不过它并不是 Google 官方公共 API，而是通过 Google Flights 当前公开搜索页面获取和解析结果。

Fli 是 Google 官方的 Google Flights MCP 吗？

不是。Fli 是社区维护的开源项目。Google 官方的 Travel Impact Model MCP 主要用于航班碳排放计算，与 Fli 的机票和航班搜索用途不同。

Google Flights MCP 可以接入 Claude Desktop 吗？

可以。使用 pipx install flights 安装后，将 fli-mcp 加入 Claude Desktop 的 MCP 配置即可。如果客户端找不到命令，可以用 which fli-mcp 获取完整路径。

Fli 支持 Google Flights 多城市查询吗？

目前不支持完整的多城市结果查询。虽然 CLI 里仍然可以看到 fli multi 命令，但按照当前 Search Transport 的说明，多城市搜索仍受限制，实际使用时建议把行程拆成多个独立航段。

Fli 可以直接订机票吗？

不能把它当成完整订票接口。当前 Booking Options 相关能力不可用，但航班结果仍可以生成 Google Flights 深度链接，再前往 Google Flights、航空公司或代理商页面继续操作。

Fli 可以用在商业项目里吗？

Fli 项目本身采用 MIT License，但它获取的是 Google Flights 数据，而且当前属于非官方访问方式。商业使用除了项目许可证，还需要自行评估 Google 相关服务条款、稳定性、限流和数据依赖风险。
